# Distribution

This document describes how Git Sentinel is packaged and distributed.

It is intended for maintainers.

## Linux bundles

Git Sentinel currently supports Linux x86_64.

The project produces:

- `.deb`
- AppImage
- Snap

The `.deb` and AppImage are generated by Tauri.

The Snap is built separately with Snapcraft.

## Tauri bundles

From the repository root:

```bash
npm run tauri -- build
```

Artifacts are generated under:

```text
target/release/bundle/
```

Current Linux bundles include:

```text
target/release/bundle/deb/
target/release/bundle/appimage/
```

## Snap

The Snap recipe lives at:

```text
snap/snapcraft.yaml
```

Supporting desktop assets live under:

```text
snap/gui/
```

### Build environment

Snapcraft and LXD are required.

On Ubuntu:

```bash
sudo snap install snapcraft --classic
sudo snap install lxd
sudo lxd init --auto
sudo usermod -aG lxd "$USER"
```

Log out and back in after adding the user to the `lxd` group.

### Build

From the repository root:

```bash
snapcraft pack
```

The Snap build uses the Tauri CLI:

```bash
npm run tauri -- build --no-bundle -- --locked
```

This is intentional.

Do not replace it with a bare:

```bash
cargo build --release
```

The Tauri CLI enables the production `custom-protocol` build path and embeds the frontend assets.

A plain Cargo build causes the application to use `devUrl` and attempt to load the frontend from the development server.

### Local installation

Install a locally built Snap with:

```bash
sudo snap install --classic --dangerous ./git-sentinel_<version>_amd64.snap
```

Run:

```bash
git-sentinel
```

Remove:

```bash
sudo snap remove git-sentinel
```

`--dangerous` is required for locally built unsigned snaps.

## Snap confinement

Git Sentinel uses:

```yaml
confinement: classic
```

This is required because the application operates as a local developer tool and needs access to the user's host environment.

Git Sentinel relies on:

- the host `git` executable;
- the user's Git configuration;
- SSH and credential helpers;
- repositories in arbitrary local paths;
- the user's terminal emulator;
- the system file manager.

Strict confinement would prevent or significantly restrict core product functionality.

Classic confinement may require manual review before publication in the Snap Store.

## Runtime requirements

Git Sentinel uses the host GTK/WebKit stack.

On Ubuntu, WebKitGTK 4.1 is required:

```bash
sudo apt install libwebkit2gtk-4.1-0
```

This is normally already available on supported Ubuntu desktop installations.

## Snap Store

The Snap Store package name is:

```text
git-sentinel
```

The name is registered to the project maintainer account.

Authentication:

```bash
snapcraft login
```

Check the active account:

```bash
snapcraft whoami
```

### Publish to edge

Build the package first:

```bash
snapcraft pack
```

Then upload it to the `edge` channel:

```bash
snapcraft upload --release=edge ./git-sentinel_<version>_amd64.snap
```

Install the Store build for validation:

```bash
sudo snap install git-sentinel --classic --edge
```

### Promote to stable

After validating the Store revision:

```bash
snapcraft release git-sentinel <revision> stable
```

Stable users can then install with:

```bash
sudo snap install git-sentinel --classic
```

## Release checklist

Before publishing a new Linux release:

- [ ] Update the application version
- [ ] Update `CHANGELOG.md`
- [ ] Run frontend tests
- [ ] Run Rust tests
- [ ] Run the production Tauri build
- [ ] Test the `.deb`
- [ ] Test the AppImage
- [ ] Run `snapcraft pack`
- [ ] Install and test the Snap locally
- [ ] Verify repository discovery
- [ ] Verify dirty/clean state
- [ ] Verify local watchers
- [ ] Verify Refresh
- [ ] Verify Fetch and Fetch All
- [ ] Verify Open in Terminal
- [ ] Verify Open Folder
- [ ] Verify persistence
- [ ] Verify the application icon and desktop entry
- [ ] Publish the GitHub release
- [ ] Upload the Snap to `edge`
- [ ] Validate the Store build
- [ ] Promote the tested Snap revision to `stable`

## Safety

Packaging must not change Git Sentinel's repository-safety model.

Git Sentinel observes repositories; it does not own them.

Removing Git Sentinel or removing a repository from Git Sentinel must never delete, move or modify the user's repository.
